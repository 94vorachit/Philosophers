## Next step

The actual bug is a lock deadlock in the monitor. In simulation.c, the monitor locks `state_lock`, then calls `all_philos_ate(sim)`, and that function locks `state_lock` again.

That means:

- monitor holds `state_lock`
- `all_philos_ate()` tries to lock `state_lock`
- the program hangs

### Fix this next

Do not call `all_philos_ate()` while `state_lock` is already locked. Replace the block with this:

```c
while (!is_stopped(sim))
{
	i = 0;
	while (i < sim->philo_count)
	{
		if (sim->must_eat > 0 && all_philos_ate(sim))
		{
			set_stop(sim);
			return (NULL);
		}

		pthread_mutex_lock(&sim->state_lock);
		if (now_ms() - sim->philos[i].last_meal_ms > sim->time_to_die)
		{
			pthread_mutex_unlock(&sim->state_lock);
			handle_death(sim, i);
			return (NULL);
		}
		pthread_mutex_unlock(&sim->state_lock);
		i++;
	}
	usleep(1000);
}
```

### Why this is the real missing step
This is the direct cause of the hang in the `must_eat` case. Once that nested lock is removed, the completion condition can terminate correctly without blocking the monitor.
